# 版本规划

## 目标分层

整个项目分成三个阶段：

### 第一阶段

先解决当前真实工作里的高频刚需，让三块业务都能在同一套链路里跑起来：

- 广告专项
- 微信小程序流量提效
- 多平台小程序接入

### 第二阶段

把每日作战、定时任务、日报、热点收集等能力自动化，形成更完整的工作辅助助手。

### 第三阶段

把大量非创造性的重复劳动尽量自动化，只把关键判断和拍板留给用户。

## 迭代节奏

- `周一到周五`：使用、记录问题、沉淀反馈
- `周六到周日`：集中开发、修复、测试、发布

## 版本边界

### 1.0

目标：先跑通主链。

包含：

- 飞书主入口
- 主控命令解析
- 飞书文本回执
- 飞书云文档草稿
- 定稿后 Notion 归档

不包含：

- 企业微信主入口
- 自动日报
- Block 工作台首页
- 复杂排版自动化

### 1.1

目标：把文档型工作真正跑顺。

包含：

- 飞书文档多轮修改闭环
- 修订请求写回原文档
- 定稿指令
- 定稿后进入归档/发布准备

### 1.2

目标：补齐非文档型工作台能力。

包含：

- 待办记录
- 当前能力现状
- 版本规划呈现
- 工作助手当前状态与最近迭代信息

这一步先求“有”，不求一步到位。

### 1.3

目标：建立工作日反馈到周末迭代的输入链路。

包含：

- 使用过程中的反馈收集
- Bug / 体验问题 / 新需求三类收口
- 周末统一迭代前的反馈池

## 当前优先级

近期优先服务这三类事情：

1. 广告实验回收、SQL 请求与下阶段方案
2. 微信需求卡片与 PRD 草稿协作
3. 多平台接入方案提炼与飞书协作修改
