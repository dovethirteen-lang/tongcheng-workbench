# 工作流全景地图

如果你不想每次都从文件夹开始看，可以直接打开：

- `08_dashboard/workflow_overview.html`

这个页面的作用不是替代具体文档，而是给你一个总览入口，让你快速判断：

- 这件事属于哪条主链路
- 应该先交给哪个 Agent
- 应该沉淀到本地、Notion 还是中间发布层
- 最终是不是要发到 Wiki
- 输入是从邮件、飞书还是 PDF 进来的

## 形态定位

这套工作台优先做成：

- `HTML 在线网页`

因为它最适合先快速搭起总控台和输入输出面板。

后续如果你想常驻桌面，再把这套页面封装成：

- `桌面 App`

也就是说，桌面 App 只是外壳，核心仍然是这张总控台页面。

## 主命令入口

这套工作流的主命令入口不是总控台页面，而是：

- `企业微信`

也就是说：

- 你在企业微信里下命令
- 主控层接收命令并处理
- 总控台页面主要承担辅助查看、状态总览和后台配置作用

总控台不是你每天必须打开才能工作的地方。

## 输入来源原则

- 数据看板：优先通过邮件订阅进入总控台
- 每日作战：允许使用飞书能力做提醒、分发和同步
- 其他事项：尽量在总控台内完成收件、加工、输出和归档
- 指令输入：默认通过企业微信进入主控层

## 输出来源原则

- 文档协作与批注：优先放在飞书云文档
- 长期归档与知识管理：优先放在 Notion
- 临时数据、脚本、过程产物：放在本地目录 `D:\Project`
- 通知与回执：优先回到企业微信

## 本地资产归档

本地化文件统一归档到：

- `D:\Project`

推荐分层：

- `D:\Project\docs`
- `D:\Project\data`
- `D:\Project\scripts`
- `D:\Project\runtime`

## 推荐看法

### 当你刚开始一天工作时

先看：

- 两条主链路
- 今天主要任务更靠近“业务执行”还是“数据实验”
- 哪几个 Agent 会参与
- 数据订阅有没有带来新的异常输入

### 当你接到一个新需求时

先问自己：

1. 原始输入是什么
2. 是广告、微信活动、平台接入还是日常管理
3. 需要沉淀进 Notion 吗
4. 最后是否要发 Wiki

### 当你感觉事情很多时

先回到全景图，而不是继续开更多文档。

它的意义是帮你从“文件视角”切回“流程视角”。
